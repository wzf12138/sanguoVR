# 实现模式库

本目录捕获 VR 三国演武场中可复用的实现模式，为后续开发提供经过验证的参考方案。模式不是强制标准，而是"遇到同类问题时推荐的做法"。

## 与其他文档的关系

- **Standards**（`standards/`）：强制规则，模式必须遵守标准。
- **Systems**（`systems/`）：工程实现指引与接口契约，模式是接口的具体应用示例。
- **Design**（`knowledge/Design/`）：产品详规，模式不定义玩法规则。

## 模式格式

每个模式文件包含：

1. **名称**：简明描述模式意图。
2. **上下文**：在什么场景下遇到此问题。
3. **方案**：推荐实现方式，含关键代码片段。
4. **理由**：为什么选择此方案。
5. **约束**：使用此模式时的注意事项。
6. **参考**：关联的标准、系统指引和 ADR。

## 预设模式类别

以下为 M01+ 实现阶段预期会积累的模式类别，当前为空骨架，随开发逐步填充：

| 类别 | 预期内容 | 触发里程碑 |
|---|---|---|
| 战斗结算 | 攻击去重、连续轨迹采样、格挡判定 | M01 |
| 武器交互 | 抓取吸附、双手持握、解卡逻辑 | M01-M02 |
| VR 移动 | 平滑移动校验、瞬移落点检测、舒适度配置 | M02 |
| 全身 IK | HMD-手柄到化身映射、命中代理同步 | M02 |
| AI 战斗 | 兵种行为选择、小队协同、公平性约束 | M03 |
| 竞技场流程 | 比赛状态机、教程步骤驱动、结算跳转 | M01, M04 |
| 数据驱动 | DataAsset 初始化、Schema 迁移、运行时覆盖 | M01+ |
| 性能优化 | 一体机渲染预算、对象池、LOD 策略 | M06 |

## 添加规则

- 模式来源：任务执行中验证有效的实现、审核中认可的方案、试玩反馈修正后的做法。
- 模式命名：`PATTERN-<类别>-<简述>.md`，如 `PATTERN-Combat-AttackDedup.md`。
- 添加模式时同步更新本索引。
- 模式失效时标记 deprecated 并说明替代方案，不直接删除。
