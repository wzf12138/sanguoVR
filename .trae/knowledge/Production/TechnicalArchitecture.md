# 技术架构

## 原则

采用 UE C++ 核心规则、蓝图编排和 Data Asset 配置的混合路线。表现层不直接决定伤害，玩家与 AI 通过不同控制源驱动同一套角色、武器、移动和战斗能力。

## 模块边界

| 模块 | 职责 |
|---|---|
| Combat | 攻击实例、连续轨迹、命中保护、格挡与统一结算 |
| Weapon | 五类武器数据、握持、有效部位、双手约束与脱手策略 |
| CharacterState | 统一生命、分部位护甲、硬直、死亡与重置 |
| Movement | 平滑移动、战术瞬移、全身占位和舒适度设置 |
| FullBodyIK | 标定、身体求解、命中映射与 IK LOD |
| SquadAI | 队伍分工、个体战术、动作请求和武将扩展 |
| GameModeFlow | 生涯、自定义、训练、结算与本地存档 |

## 数据驱动

武器、护甲、兵种、武将、AI 难度、比赛规则和训练步骤使用版本化数据资产。核心代码不得用特定武器、特定武将或 1v1 数量写死流程。

## 控制源解耦

玩家输入和 AI 决策只产生能力请求，如移动、开始攻击、格挡、抓取和使用特殊招式；角色规则验证请求并生成结果。该结构为后续联网保留边界，但一期不实现复制、匹配、服务器权威或在线依赖。

## 重置与诊断

每局使用明确生命周期管理单位、投射物、临时效果、攻击实例和 AI 黑板。开发构建记录攻击轨迹、命中拒绝原因、瞬移落点拒绝原因、AI 目标分配和帧耗时；发布构建关闭高成本诊断。
