## 关键决策 ADR 上下文

以下为架构级关键决策的补充上下文（上下文、备选方案、后果、复审条件），其他决策保持表格登记即可。

### DEC-003：战斗采用适度物理加游戏化纠正

**上下文**：VR 冷兵器战斗需要同时满足"有重量感"和"不卡死"两个矛盾目标。纯物理模拟在一体机性能下难以稳定，快速挥动会导致穿模和重复伤害；纯动画驱动则丧失 VR 手部自由度优势。

**备选方案**：纯物理约束（重量感最佳但穿模卡死风险高）→ 纯动画驱动（稳定但丧失 VR 自由度）→ 适度物理 + 游戏化纠正（选中：物理提供接触反馈，规则层纠正异常）。

**后果**：战斗结算系统（`systems/03`）需维护连续轨迹采样和攻击内去重；解卡逻辑成为长期维护点；RSK-001 和 RSK-002 直接源于此取舍。

**复审条件**：试玩认为手感失真或频繁卡死时重新评估物理/纠正比例。

### DEC-005：蓝图表现、C++ 规则、数据资产内容

**上下文**：VR 游戏需要快速迭代表现层（动画、特效、UI），同时保证战斗规则确定性。三层分离旨在让美术、程序、策划并行工作。

**备选方案**：全蓝图（迭代快但规则难确保一致）→ 全 C++（规则严谨但表现层迭代慢）→ 蓝图表现 + C++ 规则 + 数据资产内容（选中：各层职责清晰，并行度高）。

**后果**：需明确 Blueprint-C++ 边界标准（`standards/03`）；数据资产 Schema 需版本化（`standards/04`）；接口层成为关键依赖点。

**复审条件**：原型阶段实现成本异常或蓝图/C++ 边界频繁混乱时复审。

### DEC-006：AI 等级、兵种类型与队伍战术分层

**上下文**：N 对 N VR 战斗需要 AI 同时具备个体战术和队伍协作能力。一体机性能限制决定了 AI 不能使用昂贵的世界状态查询。

**备选方案**：单一行为树 + 数值缩放（简单但缺乏兵种差异）→ 多套独立行为树（差异明显但维护成本高）→ 分层架构：感知→战术评分→动作执行 + 数据驱动兵种差异（选中）。

**后果**：AI 系统（`systems/05`）需维护三层架构和稳定感知快照；调试可追踪性要求高；性能预算需为 AI 决策频率留空间。

**复审条件**：数据组合或性能成本异常时复审分层粒度。

### DEC-010：保留 UE5.8 官方 VR 模板能力；OpenXR 为主路径，PICO Neo3 为一期设备

**上下文**：VR 项目需选择引擎版本和设备目标。UE5.8 提供最新 VR 模板和 OpenXR 支持，但 PICO Neo3 运行时兼容性存在已知问题。

**备选方案**：UE5.8 + OpenXR + PICO Neo3（原选，真机验证发现不兼容）→ UE5.6 + PICO OpenXR Plugin OS5 + PICO Neo3（修正后路线，官方矩阵确认兼容）→ 更换目标设备为 PICO 4+（硬件升级但增成本）。

**后果**：项目需从 UE5.8 降级到 UE5.6 或等待 PICO 更新支持；RSK-012 和 RSK-013 源于此决策；M00-T004 因兼容性阻塞（关联 TD-001）。

**复审条件**：设备矩阵或模板基线变更时复审。

### DEC-011：玩家与 AI 通过统一角色能力接口接入

**上下文**：VR 玩家通过手柄输入，AI 通过行为树驱动。若两者使用不同战斗接口，会导致规则不一致（AI 可能绕过硬直或武器规则）。

**备选方案**：玩家和 AI 各自实现战斗逻辑（简单但一致性难保证）→ 统一角色能力接口（选中：玩家输入和 AI 决策都通过同一 API，规则层只认接口不认来源）。

**后果**：需定义稳定的角色能力 API（Attack, Block, Move, SwitchWeapon 等）；AI 系统必须通过此接口行动；接口变更影响面大。

**复审条件**：接口重构或性能异常时复审。

### DEC-013：UE 二进制资产使用 Git LFS，生成目录不入库

**上下文**：UE 项目包含大量二进制资产（.uasset, .umap, 动画, 纹理），普通 Git 会膨胀仓库。生成目录（Binaries/, Intermediate/, Saved/）不需要版本控制。

**备选方案**：不用 Git 用 UE 内置版本控制（限制大）→ 普通 Git 不加 LFS（仓库快速膨胀）→ Git LFS + .gitignore 生成目录（选中：标准做法，平衡版本控制和仓库大小）。

**后果**：需维护 .gitattributes LFS 规则和 .gitignore；LFS 存储配额需监控；RSK-014 关联此决策。

**复审条件**：Git 基线启用或存储策略变更时复审。
