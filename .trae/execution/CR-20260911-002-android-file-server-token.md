## 1. 问题

## 2. 暴露时间窗（已实测，非推断）

- **首次入库提交 = `98b2eb7`（2026-08-09，`chore: initialize UE5.8 VR project repository`）**，即**仓库初始化提交**。
  - 追溯命令：`git log --date=short -S '28DADB…A1A48A2' -- Config/DefaultEngine.ini` → 唯一命中 `98b2eb7`。

- **未核实**：该值是否为 UE 项目模板/引擎默认值（这将进一步降低其"秘密"性质）。核查方法：在引擎安装目录 `Engine/Config/` 下检索同一字符串。**本 CR 不臆测结论。**

## 3. 影响面（已收窄，逐条有理据）

| 维度 | 判断 | 依据（已实测） |
|---|---|---|
| 通道性质 | AFS 是**开发期局域网调试用的文件传输通道**，非运行时游玩链路 | UE `AndroidFileServer` 插件职责 |
| 是否随包分发 | **否** —— 该节被列入打包排除清单 | `Config/DefaultGame.ini:104-109` 的 `IniSectionDenylist` 含 `/Script/AndroidFileServerEditor.AndroidFileServerRuntimeSettings`（`:106` 先 `-` 移除、`:109` 再 `+` 加回，是 UE 控制数组顺序的标准写法，**净效果 = 在排除清单内**） |
| 当前是否生效 | **当前不生效** —— 该节内 `bCompileAFSProject=False`，AFS 未被编译进工程 | `Config/DefaultEngine.ini:171`（与 `:168` 同节） |
| 仓库可见性 | **公开可读** | 仓库公开；已推送至 `origin/master`（`f2550366827a717575332bed6a93c56d42c71f9c`） |
| 历史可回溯性 | **是** —— 该值存在于全部历史提交 | `git log -S` 追溯结果 |

**综合**：当前**无可利用面**（插件未编译 + 不随包分发），但这是一个**一旦有人启用 AFS 即立刻变为有效凭据**的沉睡风险，且已永久留在公开仓库历史中。故处置为「**轮换 + 停止跟踪**」，而非「紧急撤销」。

## 4. 处置方向（待裁定后执行，本 CR 不预置实施细节）

**推荐方案 D：轮换令牌 + 将令牌移出版本控制。**

| 选项 | 说明 | 评价 |
|---|---|---|
| **D（推荐）** | 生成新令牌；把 `SecurityToken` 从受跟踪的 `Config/DefaultEngine.ini` **移出**，改由**不被跟踪的本机配置**提供（UE 配置继承链中 `Saved/Config/…/Engine.ini` 位于项目 `Config/` 之后且已被 `.gitignore:6` 覆盖）；旧的公开值作废 | 一次解决「凭据在仓库里」的根因；后续不再复发 |
| E | 仅轮换：在 `Config/DefaultEngine.ini` 写入新令牌，仍受跟踪 | 只把旧值换成新值，**新值同样会进公开仓库**——不推荐，属掩耳盗铃 |
| F | 关闭 AFS / 清空该节 | 若确认项目不使用 AFS，成本最低；但会失去一个调试通道，且需确认无人依赖 |
| G | 改写历史移除该值 + 强制推送 | **明确否决**，理由见 §5 |

**执行前必须确认（未确认不得动手）**：
1. `SecurityToken` 移出 `DefaultEngine.ini` 后，AFS 在**需要它的场合**是否仍能取到值（UE 配置继承链的实际读取点需在编辑器内实测，不得凭文档推断）。
2. 清空/缺失 `SecurityToken` 时 AFS 的行为（是无令牌可用、还是回落到默认值）。
3. 全仓库是否还有其他 AFS 相关配置节或本机配置文件持有同一值。

## 5. 为什么明确不走「改写历史 + 强推」

1. **收益为零**：令牌当前**不生效**（§3），改写历史消除的是一个当下不可利用的值。
2. **代价极高且不可逆**：历史改写会改变 `master` 上**全部已推送提交的 SHA**，使 `f2550366` 及其之前的基线、CI 记录、LFS 对象引用、其他会话的本地副本全部失配；**一旦有任何人克隆过，就必须强制重置**。
3. **与现行红线冲突**：本项目的硬红线禁止 `git push --force`、`git reset --hard`、`git clean`。
4. **轮换本身就是标准解法**：凭据泄露的行业处置是 **rotate（作废旧值）+ 停止继续泄露**，而不是抹除历史。**旧值一旦轮换即刻失效**，历史里留下的就只是一个无用的字符串。
5. **历史即证据**：本项目刚用一整晚建立了「基线提交 + CI 绿 + 两层验收」的证据链。为抹掉一个失效字符串而重写这段历史，是拿最贵的资产去换最便宜的目标。

## 6. 遗留与后续

1. **登记为规则 23 的具体落点**：`AGENTS.md` 规则 23 已禁「提交密钥、本机路径凭据」，但**门禁脚本目前不检测明文凭据**。建议后续为 `dashboard/check-integrity.py` 增加一项「受跟踪的 `Config/*.ini` 中已知敏感键（`SecurityToken`、`*Key`、`*Secret`、`*Password`）非空即失败」的检查。**本 CR 不实施**（需另立任务，且需先过用户对"新增检查项"的批准）。
2. **同类排查未做**：本 CR 只处置了已实证的这一处。全仓库其他明文凭据**未系统排查**，故不得据此宣称"项目无凭据泄露"。
3. **该值的公开历史不追改**：旧值留在历史中，按 §5.4 接受。**注意：因用户裁定「不轮换」（§7），该值仍然有效** —— §5.4「旧值一旦轮换即刻失效」的前提**不成立**，故此处只能按「**接受该值持续暴露**」的读法执行，不得写成「已消除风险」。
