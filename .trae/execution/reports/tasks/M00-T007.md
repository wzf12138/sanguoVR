### 8.4 本轮自查出的自身缺陷（不包装、逐条留痕）

> 规则要求「不编造测试结果」的同一逻辑也要求：**自己写错的断言、自己踩的坑，必须留痕**，否则下一轮还会踩。

1. **自检第 14 项断言写反**：样本「非整数文本应抛错」，断言却写成「要求样本不抛错」⇒ 自检自己红了 1 项（13/14）。改为「3 个样本必须**全部**抛错」。**教训**：连工具的自检也会犯「期望值方向写反」这一族错误 —— 这正是第 18 条要防的「读数与结论脱钩」。
2. **TC-12 二次复跑 `git clone` 失败 rc=128**：`shutil.rmtree(..., ignore_errors=True)` 删不掉 **git pack 的只读文件** ⇒ 目标目录非空 ⇒ `fatal: destination path … already exists and is not an empty directory`。且第一次失败时**没有记录 clone 的 rc**，导致需要二轮排查。⇒ 改为「先清只读位再删」，并把 `clone rc` + stderr 前 5 行**写进证据文件**。
3. **浅克隆其实不浅（已修）**：本地路径克隆时 git 会**忽略 `--depth`**（自身打印 `warning: --depth is ignored in local clones`）⇒ 改用 `file://` URL 走智能协议，本次证据中该警告**已消失**，`--depth 1` 真正生效。**若不复看 clone 的 stderr，这条「浅克隆」会被当成事实写进报告。**
4. **HEAD 在复跑期间被推进**：`0a32773…` → `8965b97…`（提交侧入库三个资产，含 LFS）。新提交带 LFS ⇒ 默认 smudge 会让 checkout 失败 ⇒ 夹具显式 `GIT_LFS_SKIP_SMUDGE=1`（**如实标注：这不是 git 默认行为**，夹具只需要一个已提交的文本文件）。⇒ 两处 HEAD 相同这一读数取的是**当次**HEAD，报告不把它写成「与上一轮同一个 HEAD」。
5. **四处断言假阳性（全部改为结构型断言）**：① 猜格式 `readalllines=3`（实为 `行数 = 3（所用口径 readalllines）`）；② 猜措辞「表外取值」（实为「归属标签不在规范化表内」）；③ 把**说明性文字**里的 `` `System.Object[]` `` 当成「集合被串化」（真正要禁的是**读数行**出现集合，故改为排除 argv 声明行后按行判）；④ `"⇒ 通过" not in out` 撞上「报告段**完整性断言**：… ⇒ 通过」——那是**报告结构**的断言，不是判据结论 ⇒ 改为「该判据的状态行不得是 通过/未通过」。**教训：对输出做子串断言，必须断言在「结构位置」上，不能断言在全文字面量上。**
6. **报告里填过一个「没测过的值」（同轮自纠）**：§一 的 `README.md` 行，我先只测到 `SHA256[:16] = F88B09EEF75FC97E`，却**按字形补全**出一个 64 位全量 SHA256 写进报告 —— 这正是本节要防的「读数与证据脱钩」同族错误（凭印象补齐数字）。发现后立即改为**实测**值 `F88B09EEF75FC97EC0861F44D09E36E2773123A88135F31B77CE936C722CAAEE`（5,323 字节 / 58 行）。**教训：报告里的每一个十六进制串，都必须先跑一次哈希命令；不允许「按前缀补全」。**
