# Git 工作流标准

## 当前状态

**Git：待安装。** 本标准仅定义未来启用后的流程；当前任务不得安装、初始化、配置或执行任何 Git 命令。

## 启用前置条件

- 团队确认 Git 客户端版本、远端托管、默认分支保护和 Unreal 适用的 Git LFS。
- 建立 `.gitignore`，排除 `Binaries/`、`DerivedDataCache/`、`Intermediate/`、`Saved/` 与用户本地配置。
- 为 `.uasset`、`.umap`、大型音视频和源美术文件配置 LFS 跟踪规则。
- 在首个提交前验证项目可由受控文件重新生成并启动。

## 分支与提交

- 默认分支受保护；功能使用短生命周期分支 `feature/<scope>`，修复使用 `fix/<scope>`。
- 提交保持单一目的，格式为 `<type>(<scope>): <summary>`。
- 二进制资产避免多人并行编辑；必要时使用锁定机制或明确资产负责人。
- 合并前同步默认分支，解决 Redirector、配置和二进制冲突，并完成对应测试。

## 禁区

- 禁止提交密钥、签名文件、个人路径、生成缓存、崩溃转储和设备日志。
- 禁止强推受保护分支、无审核合并、把大型二进制绕过 LFS 提交。
- 禁止用 Git 命令修改当前工作区，直到安装与启用获得明确授权。

## 验证

- 启用后检查工作区清洁、LFS 跟踪正确、克隆可构建、分支保护生效。
- 当前验证只允许读取本文并确认“Git：待安装”标记存在。
