1. **TCP 短超时探测连通性**。不要用 `Invoke-WebRequest` 判断连通性（不可靠），用 TcpClient：

   $iar = $c.BeginConnect('github.com', 443, $null, $null)
   if ($iar.AsyncWaitHandle.WaitOne(5000, $false) -and $c.Connected) { '可达' } else { '不可达' }
   $c.Close()

2. **不可达或可达但 git 连接被重置/超时（TLS 层被掐）**：先试**单次借用本地活代理**推送（2026-09-03 首次实证、2026-09-10 再次实证均一次通过）：`git -c http.proxy=http://127.0.0.1:<活端口> push origin master`——仅本次命令生效，**禁止写入持久 git 配置**（严禁 `git config http.proxy`）。随后检查常见本机代理端口（7890 / 7897 / 10809 / 1080 / 8118）是否监听，再查 Windows 系统代理开关（注册表 `ProxyEnable`）。全部关闭时如实报告"网络未恢复"，停止反复空推，等用户确认网络后再试。**顺序说明**：既然「直连超时、代理可达」是本项目实测常态，当症状为 443 超时时**可直接先试代理端口**，不必先凑满 2 次直连失败。
3. **可达但 git 仍失败**：把「探测 → 成功才执行 `git push origin master`」写成临时 PowerShell 脚本循环执行：最多 30 次、每次探测超时 5 秒、间隔 60 秒，成功立即退出。脚本放系统临时目录，用完删除，绝不进项目。

     **⇒ 立法：锚点即内容。** 当 `old_string` 是**标题行 / 分隔行 / 代码围栏 / 表格结构行**时，**`new_string` 必须原样包含它**。
     **⇒ 立法：写后回读结构。** 凡编辑含结构行的文件（`.md` 正文、`.yml`、`.json`、`.py`），**写后必须回读结构**（**标题清单 / 总行数 / 表格列数 / 括号与围栏配平**），**不得只看工具返回"成功"** —— **"成功"只证明"旧串被替换了"，不证明"文件还是原来那个结构"。**
     **⇒ 附带的门禁缺口（口径已据实修正）**：`CHANGELOG.md` **无章节结构校验**。**正确口径 = 标题日期序列单调不增（允许同日多节）** —— 实测该文件 **93 个标题 / 19 个日期重复**（同日多节属正常）⇒ **「无重复日期」是错误检查项，已剔除**；能查出本次事故的是**单调性 + 孤儿内容**。`check-integrity.py` 封版中 ⇒ 并入待立项的「判据覆盖加固」批次。
    - **⚠ 字面串判据必须跑双口径（2026-09-12 两次实测，同族第 10 例）。** 以「文件或表格里是否出现某串」作判据时，**目标串常被反引号包裹** —— 直接用裸串匹配会得到**假阴性**。**本日两次实测**：① 台账第 13 行原文写作「更正 `38cd714` 提交信息…」⇒ **裸串判 `False`**；② 「截至 `1b0e34f` 已核验」⇒ **裸串判 `False`**。两次**均在下结论之前**被双口径复核拦住，**未产出错误判断**；第二次另由执行侧**自行立法**（「一律跑原样 + 去反引号双口径，再下结论」），**与本节立法独立收敛到同一结论**。
      **⇒ 立法：字面串判据一律跑「原样 + 去反引号」双口径；两口径结论不一致时回到原文字面复核，不得取其一。**
      **⇒ 同族关系（关键）：本族陷阱的出错方向是双向的** —— 既会**过松**（`.`/`\s` 在 CRLF 上假阳性，同族第 3 例），也会**过严**（反引号假阴性，本例）。**因此修正判据后若改变了判定方向，必须停手等裁决**（口径见「判据出错时执行侧怎么走」）。**「仪器取数失败 ≠ 阴性结论」与「判据口径错 ≠ 阳性或阴性结论」是同一原则的两面。**
    - **⚠ 格式跨度使字面串判据失效（2026-09-12 实测第 3 次假阴性，同族第 11 例）。** 判据串被**加粗跨度包住**时，串两侧的 `**` **不构成独立加粗跨度** ⇒ 裸串判为 `False`，而**内容确实存在**。实测：判据串「`**【用户裁定 A】**`」返回 `False`，而「`【用户裁定 A】`」返回 `True` —— **因为加粗从「【用户裁定 A】」一直延续到行末**。
      **⇒ 本族今日第 3 次同类假阴性**：①台账第 13 行（反引号）②「截至 \`1b0e34f\` 已核验」（反引号）③本次（加粗跨度）。**「双口径（原样 / 去反引号）」覆盖不到"加粗跨度"这一轴。**
      **⇒ 立法（三口径）**：字面串判据一律跑 **①原样 ②去反引号 ③去行内标记（`**` `*` `_` `~~` 与表格管道符）** 三个口径；**三者只要有一个为真即判「内容存在」，但回报必须给出全部三个口径的结论**，不得只报其一。
      **⇒ 立法（更深一层，优先于口径数量）**：**凡以字面串作判据，必须显式声明该串的"格式敏感度"** —— 它判的是**语义内容**（对格式不敏感，须归一化）还是**逐字节字面**（对格式敏感，须严格匹配）。**未声明敏感度的字面串判据一律视为缺陷判据。**
    - **⚠ 计数不等于语义：残留判定必须逐处读原文（2026-09-12 立法）。** 判「某已废弃编号/串是否仍有残留引用」时，**不得只数出现次数**。实测：`§9.4` 在 5 份文件中为 0、在 `CR-20260911-001` 与 `CHANGELOG.md` 各 1 处 —— 而**这 2 处都是"对失误本身的正当登记"**（"初稿写成 §9.4 …已改为 §9.6"），**不是残留引用**。
      **⇒ 立法：残留判定的口径是「是否存在指向已废弃对象的有效引用」，必须逐处导出原文并回报，不得只报次数。** 否则下一位执行者会把正当登记误判为残留而"修掉"它 —— **那是抹掉证据，比残留更严重。**
    - **⚠⚠ 假绿：判据「没跑」却像「跑过」（2026-09-12 实测，本族最危险的一类，同族第 12 例）。** 执行侧跑 6 条抽验判据时，**脚本把 6 条全部打印为 `True`、退出码 0**，于是它**据此执行了 `git add` → `commit`**。**根因两层**：① **PowerShell 变量名大小写不敏感** —— 视图表 `$N` 与循环变量 `$n` **是同一个变量**，第 1 轮 `$n = $N[key]` **把 `$N` 本身覆盖** ⇒ 第 2 轮起 `$N[...]` 返回 `$null`；② **赋值失败后沿用上一轮的值**（**同族第 6 例 stale 变量**，其自身立法）⇒ 更新失败的变量仍是第 1 轮的 `True`，**「合并判定」与「未通过项 = 0」全被污染**。**发现方式：读 stderr** —— stdout 照常打印 `True`、退出码 `0`，**只有 stderr 暴露了 `InvokeMethodOnNull`**。**处置（推送前完成，正确）**：未推送、未 `--amend`；换唯一变量名重做取数；加两层保险；**并明确写下「结论正确，但第一次的『方法』无效；『假绿碰巧为真』不等于判据成立」**。
      **⇒ 立法一（三态判据原则，优先级高于任何口径约定）**：**判据的输出必须能区分三态 —— 通过 / 未通过 / 未取到数。** 只有两态、且「未取到数」会塌缩进其中一态的判据**是缺陷判据**；在 fail-fast（「未通过项 = 0 即放行」）里它更会**塌缩成「通过」**。
      **⇒ 立法二（脚本化判据四项要求）**：① **必须检查 stderr 与退出码**，不得只看 stdout；② **结果变量每轮显式置空**，不得跨轮复用；③ **断言必需变量非空后再下结论**；④ **关键判据用两套独立算法交叉复核**（本次实证：正则计数 vs 行级遍历，同结论才采信）。
      **⇒ 本族出错方向至此为三类**：**过松**（`.`/`\s` 在 CRLF 上假阳性，第 3 例）／**过严**（反引号、加粗跨度假阴性，第 10、11 例）／**假绿**（判据没跑却像跑过，第 12 例）。
      **⇒ 结论（本族立法总纲）：判据的可靠性不能靠「看结果对不对」来保证，只能靠「证明它确实跑过」来保证。**
    - **⚠⚠ 假红：判据自造或不可满足，导致「内容明明合格却报未通过」（2026-09-12 实测，同族第 13 例）。** 执行侧在第十八提交抽验中，把**语义判据**「台账第 17 行 SHA = `2ed4832`」**擅自改写为字面串**「第 17 行 SHA = 2ed4832」—— **该句在文档中根本不存在**（真实形态是表格行 ``| 17 | `2ed4832` | … |``）⇒ **判据恒为 `False`、脚本 `throw` 中止**（未暂存、未提交，**零副作用**）。**⇒ 这一手同时违反了同族第 11 例的立法**：它**既未声明该串是语义判据、也未声明是字面判据**，直接拿一个自造串去匹配。
      **⇒ 危害方向与假绿相反**：**假绿会放过坏东西；假红会逼人改好东西**（或浪费一轮，或诱发次生风险 —— **"为了让判据通过而去修改内容"**）。
      **⇒ 立法（可满足性前置，强制）**：**凡字面串判据，必须先证明「该串在文中确实可满足」** —— 例如**正向扫描出至少一条候选行并导出原文**；**若扫不出候选，则该判据不成立，必须改写为语义判据**（解析结构后比对字段），**不得直接下「未通过」结论**。
      **⇒ 本族失效至此为四类**：**过松**（假阳性，第 3 例）／**过严**（假阴性，第 10、11 例）／**假绿**（没跑却像过，第 12 例）／**假红**（不可满足却像没过，第 13 例）。**四类共同点：都与「内容对不对」无关，都是判据自身不可信。**
    - **⚠ 工具层三态：`$Error.Count` 不是三态信号（2026-09-12 实测，同族第 13 例配套）。** 执行侧为防假绿而加 `Set-StrictMode -Latest` + `$ErrorActionPreference='Stop'`，结果 **`git push` 成功**（进度信息写 **stderr**）**却被视为终止性错误** ⇒ 脚本在推送后中断、返回 `exit code 1`。**若照抄输出就会报「推送失败」—— 又是一次假红。** 处置正确：**先只读确认**（`origin/master == HEAD`）判定推送已落地，再把 native 调用改回 `Continue` + **显式检查 `$LASTEXITCODE`**。实测 `$Error.Count` = **32，全部来自 git 写 stderr 的进度行**，与逻辑失败无关。
      **⇒ 立法**：**「命令写了 stderr」≠「命令失败」**；**native 命令的权威三态信号 = `$LASTEXITCODE` + 显式非空断言 + 双算法一致**。
      **⇒ 配置自身的陷阱**：**`$ErrorActionPreference='Stop'` 与「会正常写 stderr 的命令」天然冲突**（把正常当失败）；**`'Continue'` 与「忽略真实失败」天然冲突**（把失败当正常）。**两种配置各会制造一类假信号 ⇒ 必须靠显式退出码检查兜住，不能靠全局偏好设置。**
    - **⚠ 匹配方式未声明：精确相等 / 前缀 / 子串（2026-09-12 实测，同族第 14 例）。** 决策侧在提单中写「新增小节 `### 活动区规格（按人数计）` 存在（= 1）」，而**实际标题带状态后缀**「`### 活动区规格（按人数计） —— 待定（不得用作验收依据）`」⇒ **逐字相等 = 0，前缀匹配 = 1**。执行侧按**前缀**判定并**显式回报口径差异**（正确），**未擅自改文件**。
      **⇒ 立法**：**凡以字面串作判据，除声明「格式敏感度」外，必须同时声明「匹配方式」** —— **精确相等 / 前缀 / 子串**三者之一。**未声明匹配方式的字面串判据，同样视为缺陷判据。**
      **⇒ 本次裁定**：**文件是对的，错的是判据** —— 标题后缀是**有意设计**（让只扫标题的人也能看到「待定」状态）⇒ **不改标题。**
    - **⚠ 量具伪影：`git show` + join 计行会周期性制造假红（2026-09-12 第 2 次实测，同族第 15 例）。** 结构回读用 `git show <SHA>:<path>` 输出后 **join 计行**，报「提交产物 1105 / 工作区 1106 ⇒ 不一致」。**改用字节导出法**（`git show` 重定向到文件 → `ReadAllText`）后：**5 文件 SHA256 全同、字节长度全同、LF 归一全同、行数 = 基准值** ⇒ **判定为量具伪影，不是内容差异**（第 1 次为 1083 vs 1084）。执行侧**未推送、先查清**（正确）。
      **⇒ 立法：结构回读一律用字节导出法，禁止用 `git show` + join 计行。** 否则会**周期性制造假红**，而**假红的代价是逼人去改本来正确的东西**（同族第 13 例）。
    - **⚠ 工具层：显示串与 `-f` 冲突（2026-09-12 实测）。** PowerShell 把 `("{7,}")`、`("{1,}")` 中的 `{…}` 当作**格式占位符** ⇒ 该显示行抛错未打印。**关键：判据本身仍执行**（断言基于变量而非打印文本），fail-fast 未受影响；但**「脚本没报错」不能证明判据跑过** ⇒ 执行侧用修正格式串单独重测并贴原始输出（正确）。
      **⇒ 立法**：**显示串里凡含正则量词 `{m,n}`，必须与 `-f` 隔离**（先赋值再拼串）。**并且：「脚本没报错」不是「判据跑过」的证据**（与第 12 例同源）。
