# UE Bridge MCP 刷新流程（ue-bridge 失联时按序执行）

> 本文是本主题唯一权威正文，其他文档只链接、不复制步骤。
> 适用对象：所有需要调用 ue-bridge MCP 工具的 AI 模型（执行、决策、审核）。
> 用户铁律：**先探活、后刷新**——MCP 是通的绝不做刷新动作；需要刷新时全程自主连续执行、禁止逐步向用户请示；刷新前**必须确认 UE 完全启动**，UE 未运行禁止空刷。

## 为什么需要

TraeWork 里的 ue-bridge MCP 在虚幻引擎（UE）重启后会断开与编辑器的连接，需要在 TraeWork 设置 → MCP → 右上角刷新后才能恢复。本流程让 AI 自主判断、自主修复，避免两个极端：MCP 正常时白刷一遍浪费用户时间（已发生，用户明确纠正），以及失联时干等用户手动处理。

## 决策顺序（严格按序执行，禁止跳步）

```
调用 ue-bridge 工具（探活）
 ├─ 正常返回 ──→ MCP 通路正常：直接继续原任务，禁止走刷新流程
 └─ 失败/超时/报错
      └─ 判断 UE 是否正在运行
           ├─ 未运行 ──→ 禁止刷新（刷了也无效）：等待 UE 启动或告知用户
           └─ 正在运行
                └─ 确认 UE 完全启动（三条判据 + 轮询等待）
                     └─ GUI 刷新 MCP ──→ 复测探活
                          ├─ 通过 ──→ 回到原任务
                          └─ 仍失败 ──→ 按阻塞上报（CK-04）
```

触发场景（满足其一即执行上述决策顺序）：

- UE 刚被重启（无论谁重启，含执行模型自己的 build-and-relaunch、PIE 崩溃后重启）。
- ue-bridge 工具调用失败、超时或行为异常。

## 第一步：探活（判断 MCP 通不通）

- 调用一个轻量 ue-bridge 工具，推荐 `get-project-info`（不带参数）。
- **判定通过**：工具调用正常返回（包括返回占位文本 "Structured result ready"，这是该 MCP 的正常响应格式，视为通过）。
- **判定失败**：调用报错、超时、无响应或返回明确错误信息。
- **探活通过 → 立即结束本流程，直接继续原任务，禁止任何刷新动作。**
- 注意：探活通过不代表编辑器内所有能力可用；若后续实际关卡/资产操作持续异常，回到本流程重走一遍。

## 第二步：判断 UE 是否正在运行

- 用应用列表/进程列表确认 UE 编辑器进程（UnrealEditor）是否存在。
- **未运行 → 禁止刷新**：UE 没开时刷新无意义。告知用户"ue-bridge 失联且 UE 未运行，等 UE 启动后再处理"，或按任务上下文等待 UE 启动后回到第三步。

## 第三步：确认 UE 已完全启动（硬性门禁，禁止跳过）

"完全启动" = 以下三条**同时满足**：

1. **进程存在**（第二步已确认）。
2. **编辑器渲染完成**：对 UE 进程截图，能看到完整编辑器界面（视口、工具栏、面板），没有启动 Splash 或加载进度条。
3. **关卡已加载**：视口中已显示场景内容（即用户说的"已进入场景"）。

等待策略：

- UE 冷启动通常需要 1～3 分钟，启动后前 2 分钟内大概率未就绪，先等待再检查。
- 每 30 秒复查一次，最多等待 10 分钟。
- 超时仍未就绪 → **停止本流程**，告知用户"UE 未完全启动，暂缓刷新 MCP"。

## 第四步：GUI 刷新（自主连续完成，全程 0 次向用户确认）

> 每次点击后重新截图定位下一个元素，属于 AI 内部定位动作，必须做；这不是向用户确认，不得借此请示用户。

1. **定位 TraeWork**：用应用列表获取 TraeWork 当前进程 pid（每次会变，禁止沿用旧值）。
2. **截图当前界面**：获取 TraeWork 主窗口截图，确认设置弹窗是否已打开。
3. **打开设置**：若未打开，点击主窗口左下角、用户头像附近的设置入口（以当次截图实际位置为准），弹出设置窗口。
4. **进入 MCP 页**：点击设置左侧菜单"MCP"（位于"权限审批"与"模型"之间）。
5. **点击刷新**：点击"MCP Servers 管理"卡片右上角的刷新按钮（↻ 圆形箭头图标，"+ 添加"按钮左侧）。只点这个全局刷新按钮，**不要**逐台点服务器行的"重试"链接。
6. **复测探活**：回到第一步再调一次 `get-project-info`，正常返回即恢复完成；仍失败按阻塞上报（CK-04），不得虚构"已恢复"。

全程一口气完成，目标 1 分钟内结束，中途不询问用户。

## 本机已验证的工具坑（照做，避免反复试错）

- `click` 的 `element_id` 是必填参数。TraeWork 是 Electron 界面，可访问性树很浅、大部分控件无独立元素 id：传主内容 pane 的 id 充当 `element_id`，同时提供 x/y 坐标兜底。
- 截图返回 "no-change"（差异模式）时，加 `disableDiff=true` 强制返回完整截图。
- 坐标是窗口内相对像素，分辨率、缩放或窗口尺寸变化后位置会漂移：**每次以当次截图重新定位，禁止硬编码历史坐标**。
- `get-project-info` 返回占位文本是该 MCP 的正常响应格式，探活时视为**通过**；连接成败最终以实际关卡/资产操作是否正常为准。

## 失败处理

- 任一界面元素定位失败：重新截图定位再试一次；仍失败 → 告知用户具体卡在哪一步，请用户手动刷新。
- 刷新后复测探活仍失败 → 按阻塞上报（CK-04），不得隐瞒或虚构"已恢复"。
